# LifeLog · 生活记录
大部分内容是直接vibecoding的，起初是想做一个简易的网页自己用，比较简陋，但是个人感觉一个人用起来还行，欢迎大家尝试呀~

> 一个纯前端的个人生活记录站：任务、习惯打卡、日记、复盘与数据洞察，放在同一条时间轴上。
>
> **在线体验**：<https://lifelog-16154.app.workbuddy.host/#/login>  
> (<https://angela-ning.github.io/lifelog/>待进一步更新）  
> **源码仓库**：<https://github.com/angela-ning/lifelog>
>
> 打开即用，无需注册邀请。所有记录**只保存在你自己的浏览器里**，不上传任何服务器。详见 [数据与隐私](#6-数据与隐私)。

`React 18` · `TypeScript 5` · `Vite 5` · `IndexedDB` · `MIT License`

## 1. 设计目标

个人记录类工具的失效，通常不是因为功能不足，而是因为下列四个断点。本项目针对这四点分别做了处理：

| 问题           | 常见结果       | 本项目的处理方式                                                                          |
| ------------ | ---------- | --------------------------------------------------------------------------------- |
| 待办散落在各处      | 反复惦记，心理负担大 | 每件事落成一条**可执行的下一步行动**，用子清单拆分，进度按完成情况自动计算（GTD）                                      |
| 分不清「忙」与「重要」  | 时间被紧急事项占满  | **艾森豪威尔四象限**视图，直接看出任务集中在哪个象限                                                      |
| 习惯依赖意志力     | 中断一次即放弃    | 五种打卡周期 + 周期进度 + 连续天数 + 7/21/66/100 天里程碑，以低门槛方式持续（Fogg 行为模型；习惯形成的中位时长约 66 天）       |
| 只记录不回看       | 记录逐渐失去意义   | 提供模板降低记录成本，再通过**周 / 月 / 季复盘**与**数据洞察**把记录转化为结论                                    |

一句话概括：这不是又一个效率工具，而是让「做过的、坚持过的、想过的事」最终都能被回看。

## 2. 功能总览

### 页面与能力

| 页面   | 路由           | 说明                                                                                                                                                |
| ---- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 今日概览 | `/`          | 指标卡（进行中与待办数、逾期及 3 天内到期、今日待打卡、本周完成、连续记录天数）；**今日聚焦**（临近到期任务，最多 6 条，可直接勾选完成）；**今日打卡**；今日记录；近 14 天完成趋势；活跃日历；最近任务                                     |
| 任务   | `/tasks`     | 关键词搜索（标题 / 摘要 / 正文）、领域与优先级筛选、排序（优先级 / 截止日 / 进度 / 创建时间）、状态切换、标签筛选、**列表 / 四象限双视图**、新建任务                                                             |
| 任务详情 | `/tasks/:id` | 状态与进度环（子清单非空时进度由完成比例自动推导，全部勾选后自动置为 100% 并写入完成时间）；子清单管理；**Markdown 编辑与预览**；**附件上传**（预览 / 下载 / 插入正文）；**时间投入记录**（+15 / +25 / +50 分钟）；属性设置；更新记录；归档 / 删除 |
| 打卡   | `/habits`    | **五种周期**：每天、指定星期、每周 N 次、每月 N 次、每 N 天；周期进度与 `N/M`；连续天数与最长连续；**7 / 21 / 66 / 100 天里程碑**；近 **12 周热力图**；打卡与取消；顶部汇总今日完成率、平均周期进度、最长连续                   |
| 生活日志 | `/journal`   | 按日期浏览（日期选择器 + 最近 20 篇）；标题与 Markdown 正文；**心情 1–5**、**精力 1–5**；天气、地点；标签；**三件好事 / 今日复盘 / 情绪记录**三个内置模板；当日照片与附件；同一天仅保留一篇（再次保存即合并）                       |
| 复盘   | `/reviews`   | 周 / 月 / 季度切换；**用数据生成模板**（汇总该周期数据后生成结构化作答框架）；Markdown 正文；自评分 1–10；预览；本周期数据面板；历史复盘列表；同一周期重复保存将覆盖                                                   |
| 数据洞察 | `/insights`  | 近 30 天完成趋势、心情与精力曲线、任务领域分布、四象限分布、打卡完成率排行、活跃日历                                                                                                     |
| 关于   | `/about`     | 各模块的设计依据（GTD、四象限、Fogg 行为模型、Lally 2010、表达性写作、PDCA、Quantified Self）与建议用法                                                                            |
| 设置   | `/settings`  | 账号资料（昵称 / 简介 / 头像颜色）、修改密码、标签管理（增删 + 8 种颜色）、**导出 / 导入 JSON 备份**、清空数据                                                                               |

### 通用能力

- **登录认证**：注册 / 登录 / 退出。密码经 **PBKDF2-SHA256（10 万次迭代 + 16 字节随机盐）** 派生后存储，明文不落盘；会话有效期 30 天。
- **多账号数据隔离**：所有读写均带 `owner_id` 条件，页面层无法取得其他账号的数据。
- **Markdown 渲染**：`remark-gfm`（表格、任务列表）+ `rehype-raw` + `rehype-sanitize`（HTML 白名单清洗）+ `rehype-highlight`（代码高亮）。
- **四类附件解析**：`.md / .txt` 直接渲染；`.docx / .doc` 转换为 HTML（mammoth）；`.pdf` 逐页抽取文本（pdfjs-dist）；图片直接预览。单文件上限 20 MB，支持拖拽批量上传。PDF 与 Word 解析器**按需动态加载**，首屏 JS 体积由 1.45 MB 降至 785 KB。
- **响应式布局**：侧边导航 + 内容区，窄屏可用。

## 3. 快速开始

### 环境要求

- Node.js **≥ 18**（开发与验证环境：Node.js 22.x）
- npm（随 Node.js 安装）
- 现代浏览器（Chrome / Edge / Safari / Firefox，需支持 IndexedDB 与 WebCrypto）

无需数据库、后端服务、环境变量或密钥。Windows 环境下偶发的 rollup 原生二进制缺失问题已通过 `optionalDependencies` 处理，其他平台会依据 `os` / `cpu` 约束自动跳过。

### 安装与启动

```bash
git clone https://github.com/angela-ning/lifelog.git
cd lifelog
npm install
npm run dev
# → http://127.0.0.1:5173
```

### 常用命令

| 命令                | 说明                            |
| ----------------- | ----------------------------- |
| `npm run dev`     | 启动开发服务器（127.0.0.1:5173）       |
| `npm run build`   | TypeScript 类型检查 + 生产构建，产物在 `dist/` |
| `npm run preview` | 本地预览构建产物                      |
| `npm run selftest` | 日期与打卡周期核心逻辑自检（20 项断言）         |

## 4. 部署

### GitHub Pages

仓库已内置 `.github/workflows/deploy.yml`，推送到 `main` 后自动构建并发布。

1. 仓库 → **Settings → Pages**；
2. **Source** 选择 **GitHub Actions**；
3. 此后每次推送到 `main`，Actions 会执行安装依赖、自检、构建并发布。

站点地址为 `https://angela-ning.github.io/lifelog/`。由于 `vite.config.ts` 使用 `base: './'`、路由采用 `HashRouter`，部署在子路径下同样可正常访问。`dist/` 已在 `.gitignore` 中忽略，构建产物由 Actions 生成。

发布成功后，建议将仓库 About 中的 **Website** 字段填写为该地址。

### 其他静态托管

```bash
npm run build
# 将 dist/ 上传至对象存储、Nginx 或任意静态托管即可
```

## 5. 使用说明

### 首次使用

1. 打开站点后点击「注册」，填写邮箱、昵称与密码（密码至少 6 位）；
2. 注册完成后自动登录并进入「今日概览」；
3. 建议先在「设置」中创建常用标签（如 `深度工作`、`运动`、`家人`），任务与日志均可挂载标签。

> 数据保存在**当前浏览器**中，不会上传服务器。更换浏览器或设备、清除浏览器数据都会导致数据不可见，**请定期在「设置 → 数据备份」中导出 JSON**。
>
> 线上版与本地版是**两个相互独立的数据空间**：在线上注册的账号在本机 `127.0.0.1:5173` 不存在，反之亦然。

### 每日建议流程

| 时机    | 操作                                    |
| ----- | ------------------------------------- |
| 早晨    | 打开「今日概览」，确认当天必须推进的三件事（可用四象限筛选「重要不紧急」） |
| 执行过程中 | 在任务详情页记录时间投入                          |
| 日常     | 完成当日打卡，进度条显示当前周期剩余次数                  |
| 晚间    | 在「生活日志」记录数句，标注心情与精力；难以展开时使用「三件好事」模板    |
| 周末    | 在「复盘」中生成周期模板，总结「做得好的 / 受阻的 / 下一步」     |

### 常用操作路径

| 目标      | 路径                                        |
| ------- | ----------------------------------------- |
| 新建任务    | 任务页 → 新建任务 → 填写标题、领域、优先级、预估时长 → 保存        |
| 拆分任务    | 任务详情 → 子清单逐条添加，进度自动按完成比例计算                |
| 编写任务详情  | 任务详情 → Markdown 编辑区输入 → 切换「预览」查看渲染结果 → 保存 |
| 上传参考文件  | 任务详情 / 日志 → 附件区点击或拖拽上传 → 预览 / 插入正文 / 下载   |
| 创建打卡    | 打卡页 → 新建打卡 → 选择周期类型并填写星期、目标次数或间隔天数        |
| 打卡      | 打卡页点击「完成今日打卡」（可再次点击取消），概览页同样支持            |
| 撰写日志    | 生活日志 → 选择日期 → 填写标题与正文 → 调整心情与精力 → 保存      |
| 周期复盘    | 复盘 → 选择周期 → 用数据生成模板 → 补充内容 → 自评分 → 保存     |
| 备份数据    | 设置 → 导出 JSON 备份（`lifelog-backup-YYYY-MM-DD.json`） |
| 恢复数据    | 设置 → 导入备份，按记录 ID 覆盖，可重复导入                 |
| 修改密码    | 设置 → 修改密码，需验证当前密码                         |

## 6. 数据与隐私

- **存储方式**：浏览器 IndexedDB，数据库名 `lifelog`，包含 `users`、`tasks`、`habits`、`checkins`、`journals`、`attachments`、`tags`、`reviews`、`settings`、`files` 等表。
- **账号安全**：密码经 PBKDF2-SHA256（10 万次迭代 + 随机盐）派生后存储，明文密码不落盘；会话信息存于 `localStorage`（键 `lifelog.session`，有效期 30 天）。
- **附件存储**：二进制数据存放于 `files` 表，业务表仅保存元信息与 `storage_key`。
- **数据隔离**：所有数据按 `owner_id` 隔离。
- **不上传服务器**：清除浏览器数据会一并清除记录，建议每月导出一次备份。

### 线上版本说明

线上版与本地版为同一份代码，区别仅在于打开方式 —— 服务端只负责分发静态页面，不保存任何记录。

| 项目      | 说明                                            |
| ------- | --------------------------------------------- |
| 数据相互独立  | 任何人打开站点都是一个空白实例，需自行注册账号；不同使用者之间数据互不可见           |
| 服务端无数据  | 没有中央数据库，服务端不接触任何记录与密码；站点公开，数据私有                |
| 数据随浏览器  | 线上版与本地版账号不互通；更换浏览器、设备或清理缓存后原数据不可见              |
| 跨设备     | 目前通过 JSON 备份导入导出实现；接入云端数据库的改造方式见[项目结构](#8-项目结构) |

## 7. 常见问题

**数据会丢失吗？**
只要不清除浏览器数据或卸载浏览器，数据会持续保留。但因数据仅存本地，更换浏览器或设备后不可见，因此建议每月导出一次 JSON 备份。

**可以在手机或其他设备上查看吗？**
当前不支持，这是本地存储模式的固有限制。如需跨设备，需要接入云端数据库。

**为什么需要注册？**
登录用于在同一台设备上区分不同使用者的数据，所有读写均带 `owner_id` 过滤；同时也为将来接入云端保留了账号体系。

**使用成本高吗？**
日常使用约为每天 5 分钟：早晨确认三件事，执行中记录投入，完成打卡，晚间记录数句，周末做一次复盘。

**可以二次开发吗？**
可以。项目基于 MIT 协议开源，数据层集中在 `src/lib/`，页面逻辑位于 `src/pages/`，改造成本较低。

```
src/lib/auth.ts   # 账号与会话（当前为本地 PBKDF2）
src/lib/repo.ts   # 数据访问层（对外接口保持不变）
```

## 9. 已知限制

- 数据仅存于本机浏览器，**不支持跨设备同步**；更换设备需手动导出与导入 JSON（附件二进制不在备份文件中）。
- 线上版本为公开可访问的站点，任何人打开都可自行注册，但各使用者数据相互独立。
- PDF 仅做文本抽取，扫描件（图片型 PDF）未经过 OCR，预览结果可能为空。
- 单个附件上限为 20 MB。
- 无消息提醒与推送，无移动端原生应用（网页采用响应式布局）。
- 首屏 JS 约 785 KB（gzip 后 247 KB），包含 Markdown 渲染与代码高亮依赖，尚未进一步分包。

欢迎提交 issue 或 fork 后自行修改。
