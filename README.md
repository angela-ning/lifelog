# 生活记录 · LifeLog

> ### 🌐 在线体验 → **<https://lifelog-16154.app.workbuddy.host/>**
> ### 📦 源码仓库 → **<https://github.com/angela-ning/lifelog>**
>
> 打开就能用，不需要注册邀请。**你记录的内容只保存在你自己的浏览器里** —— 不上传任何服务器，作者看不到任何人的数据。详见 [数据存储与隐私](#6-数据存储与隐私)。

本项目大部分内容是经过vibecoding完成的，起初做这个是想用于个人的记录，欢迎大家体验~

这是一个给自己用的私人档案站：**任务记录 + 打卡习惯 + 生活日志 + 周/月/季复盘 + 数据洞察**，把「要做的事」和「活过的日子」放进同一条时间轴。

纯前端应用，`React 18 + TypeScript + Vite`，数据存浏览器 IndexedDB，**不需要服务器、不需要配置任何环境变量**，`npm install` 完就能跑；线上部署的那一份用的就是同一套代码（见顶部链接）。

`React 18` · `TypeScript 5` · `Vite 5` · `IndexedDB` · `MIT License`

## 1. 项目解决什么问题

日常记录类工具的失败通常不在「功能不够」，而在下面四个断点，本项目逐条对应处理：

| 痛点               | 常见结果          | 本项目怎么做                                                                           |
| ---------------- | ------------- | -------------------------------------------------------------------------------- |
| 待办散落在便签、聊天记录和脑子里 | 忘事、反复惦记，心理负担大 | 每件事落成一条**可执行的「下一步行动」**，用子清单拆细，进度自动算（GTD）                                         |
| 分不清「忙」和「重要」      | 时间全被紧急事项吃掉    | **艾森豪威尔四象限**视图，一眼看出任务堆在哪个格子                                                      |
| 习惯靠决心，断一天就全盘放弃   | 坚持两周后归零       | 五种打卡周期 + 周期进度条 + 连续天数 + 7/21/66/100 天里程碑，用「小到不会失败」的方式重建（Fogg 行为模型 / 习惯形成中位 66 天） |
| 记录只增不减，从不回看      | 写了也没用，慢慢就不写了  | 记录时给**三件好事**等模板降低门槛，之后用**周/月/季复盘**和**数据洞察**把记录变成结论                               |

一句话概括：不是再做一个效率工具，而是让「做过的、坚持过的、想过的事」最后都能被回看。

## 2. 主要功能

### 页面与能力

| 页面   | 路由           | 实装功能                                                                                                                                                                   |
| ---- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 今日概览 | `/`          | 四张指标卡（进行中/待办 + 逾期与 3 天内到期数、今日待打卡、本周完成、记录连续天数）；**今日聚焦**（最近到期任务，最多 6 条，可直接勾选完成）；**今日打卡**（一键打卡）；**今天的记录**；**近 14 天完成趋势**；**活跃日历**；**最近任务**                                |
| 任务   | `/tasks`     | 关键词搜索（标题 / 摘要 / 正文）、领域筛选、优先级筛选、排序（优先级 / 截止日 / 进度 / 创建时间）、状态切换（全部 / 待办 / 进行中 / 已完成 / 已归档）、标签筛选、**列表 / 四象限双视图**、新建任务                                                     |
| 任务详情 | `/tasks/:id` | 状态与进度环（子清单非空时进度由清单完成比例**自动推导**，勾完自动 100% 并写入完成时间）；子清单增删勾选；**Markdown 编辑 / 预览**；**附件上传**（预览 / 下载 / 一键插入正文）；**时间投入**（+15 / +25 / +50 分钟）；属性（领域、优先级、截止日、开始日）；更新记录；归档 / 删除 |
| 打卡   | `/habits`    | **五种周期**：每天、指定星期、每周 N 次、每月 N 次、每 N 天；当前周期进度条与 `N/M`；连续天数与最长连续；**7 / 21 / 66 / 100 天里程碑**；近 **12 周热力图**；今日一键打卡（可取消）；归档 / 删除；顶部汇总今日完成率、周期平均进度、最长连续                       |
| 生活日志 | `/journal`   | 按日期流（日期选择器 + 最近 20 篇）；标题；Markdown 正文与预览；**心情 1–5**、**精力 1–5**；天气、地点；标签；**三件好事 / 今日复盘 / 情绪记录**三个快速模板；当天的照片与附件；同一天只保留一篇（保存即合并）                                           |
| 复盘   | `/reviews`   | 周 / 月 / 季度切换；**「用数据生成模板」**——自动汇总该周期数据后生成结构化作答框架；Markdown 正文；自评分 1–10；预览；本周期数据面板；历史复盘列表；同一周期重复保存会覆盖                                                                     |
| 数据洞察 | `/insights`  | 近 30 天完成趋势、心情与精力曲线、任务领域分布、四象限分布、打卡完成率排行、活跃日历                                                                                                                           |
| 关于   | `/about`     | 每个板块的设计依据（GTD、四象限、Fogg、Lally 2010、表达性写作、PDCA、Quantified Self）与「每天 5 分钟」用法                                                                                              |
| 设置   | `/settings`  | 账号资料（昵称 / 简介 / 头像颜色）、修改密码、标签管理（增删 + 8 色）、**导出 / 导入 JSON 备份**、清空全部数据                                                                                                    |

### 通用能力

- **登录认证**：注册 / 登录 / 退出。密码用 **PBKDF2-SHA256（10 万次迭代 + 16 字节随机盐）** 派生后存储，明文不落盘；会话有效期 30 天，刷新不掉线。
- **多账号数据隔离**：所有读写都带 `owner_id` 条件过滤，页面层拿不到别的账号的数据（等价于云端的行级权限）。
- **Markdown 渲染**：`remark-gfm`（表格 / 任务列表）+ `rehype-raw` + `rehype-sanitize`（原始 HTML 白名单）+ `rehype-highlight`（代码高亮）。
- **四类附件解析**：`.md / .txt` 直接渲染；`.docx / .doc` 转 HTML（mammoth）；`.pdf` 逐页抽取文本（pdfjs-dist）；图片直接预览。单文件 ≤ 20 MB，支持拖拽批量上传。PDF / Word 解析器**按需动态加载**，不拖慢首屏（首屏 JS 从 1.45 MB 降到 785 KB）。
- **响应式布局**：侧边导航 + 内容区，窄屏可用。

## 3. 安装方法

### 只想试用，不想装环境？

直接打开 **[lifelog-16154.app.workbuddy.host](https://lifelog-16154.app.workbuddy.host/)** 就行，功能与本机运行完全一致。下面这一段是给「想自己跑一份」或「想改代码」的人看的。

### 环境要求

- Node.js **≥ 18**（本项目在 Node.js 22.x 上开发验证）
- npm（随 Node 一起安装）
- 现代浏览器（Chrome / Edge / Safari / Firefox 均可，需支持 IndexedDB 与 WebCrypto）
- 依赖不含需要编译的原生模块；Windows 上 npm 偶发漏装 rollup 原生二进制的情况已用 `optionalDependencies` 兜底，其他平台会因 `os` / `cpu` 限制自动跳过，不影响安装。

不需要数据库、不需要后端、不需要任何环境变量或密钥。

### 安装与启动

```bash
# 1. 拿到代码（也可以在 GitHub 页面点 Code → Download ZIP 解压）
git clone https://github.com/angela-ning/lifelog.git
cd lifelog

# 2. 安装依赖
npm install

# 3. 启动本地开发服务器
npm run dev
# → http://127.0.0.1:5173
```

### 生产构建与预览

```bash
npm run build     # tsc 类型检查 + Vite 构建，产物在 dist/
npm run preview   # 本地预览构建产物
```

`vite.config.ts` 中 `base: './'`，`dist/` 可直接丢到任意静态托管（GitHub Pages、对象存储、Nginx），无需配置路由重写之外的服务端能力。

### 部署到 GitHub Pages

仓库里已经放好 `.github/workflows/deploy.yml`，推上去后只需在 GitHub 页面上开通一次：

1. 仓库 → **Settings → Pages**；
2. **Source** 选 **GitHub Actions**（不要选 Deploy from a branch，让云端重新构建更干净）；
3. 之后每次 push 到 `main`，Actions 会自动 `npm ci` + `npm run build` 并发布。

网址形如 `https://<你的用户名>.github.io/lifelog/`。因为 `vite.config.ts` 用的是 `base: './'`、路由是 `HashRouter`，放在这种子路径下也不会白屏。（`.gitignore` 里忽略了 `dist/`，构建产物交给 Actions 生成。）

### 构建产物直接丢到任意静态托管

```bash
npm run build     # 产出 dist/
# 把 dist/ 整个目录上传到对象存储 / Nginx / 任意静态托管即可
```

### 自检

```bash
npm run selftest  # 运行日期与打卡周期统计的核心逻辑自检（20 项断言）
```

## 4. 使用方法

### 第一次使用

1. 打开 `http://127.0.0.1:5173/`，点「注册」，填写邮箱 + 昵称 + 密码（**密码至少 6 位**）。
2. 注册成功会自动登录并跳转到「今日概览」。
3. 建议先去「设置」里建几个常用标签（如 `深度工作`、`运动`、`家人`），后面任务和日志都能挂标签。

> 数据保存在**当前这台电脑的浏览器**里，不会上传到任何服务器。换电脑、换浏览器、清除浏览器数据都不会保留，请定期在「设置 → 数据备份」里导出 JSON。
>
> 线上版与本地版是**两个互不相通的空间**：在线上注册的账号，在本机 `127.0.0.1:5173` 上并不存在，反过来也一样。

### 每天 5 分钟的用法

| 时机    | 做什么                                          |
| ----- | -------------------------------------------- |
| 早上    | 打开「今日概览」，确认今天必须推进的 3 件事（任务页可用四象限把「重要不紧急」挑出来） |
| 做的过程中 | 在任务详情点 `+25 分钟` 记录投入，别靠回忆                    |
| 顺手    | 完成今日打卡，进度条会告诉你这个周期还差几次                       |
| 晚上    | 在「生活日志」写 3–5 句，标一下心情和精力；写不出来就用「三件好事」模板       |
| 周末    | 到「复盘」选「周复盘」→「用数据生成模板」，回答「做得好的 / 卡住的 / 下一步」   |

### 关键操作路径

| 想做的事   | 怎么做                                                     |
| ------ | ------------------------------------------------------- |
| 建一个任务  | 任务页 →「新建任务」，填标题、领域、优先级、预估时长 → 保存                        |
| 把任务拆细  | 任务详情 →「子清单」逐条添加（如「收集票据」「扫描命名」「录入表格」），进度自动按完成比例计算        |
| 写任务细节  | 任务详情 →「任务详情（Markdown）」编辑区输入，切「预览」看渲染结果，点保存              |
| 上传参考文件 | 任务详情 / 日志 → 附件区点击或拖拽上传，点 👁 预览、📎 插入正文、⬇ 下载             |
| 建打卡    | 打卡页 →「新建打卡」，选周期类型，按需填星期 / 目标次数 / 间隔天数 / 起止日期            |
| 打卡     | 打卡页点「完成今日打卡」（可再点一次取消）；概览页也能直接打                          |
| 写日志    | 生活日志 → 选日期 → 填标题与正文 → 拉动心情 / 精力滑块 → 保存                  |
| 做复盘    | 复盘 → 选周期（周 / 月 / 季度）→「用数据生成模板」→ 补完内容 → 打自评分 → 保存        |
| 备份数据   | 设置 →「导出 JSON 备份」，文件名形如 `lifelog-backup-2026-09-29.json` |
| 恢复数据   | 设置 →「导入备份」选择 JSON（按记录 ID 覆盖，可重复导入）                      |
| 改密码    | 设置 →「修改密码」，需验证当前密码                                      |

### 从本机模式切换到云端

数据模型的字段命名（`owner_id` / `created_at` / `updated_at` …）已按云端 Postgres 表结构约定写好，迁移时**只需替换三个文件**的实现，页面代码一行不用改：

```
src/lib/db.ts     # 持久化层（当前为 IndexedDB）
src/lib/auth.ts   # 账号与会话（当前为本地 PBKDF2）
src/lib/repo.ts   # 数据访问层（对外接口保持不变）
```

## 5. 输入 / 输出示例

### 5.1 任务正文：Markdown 输入 → 页面渲染

在任务详情的 Markdown 编辑区输入：

````markdown
# 家庭财务档案 · 执行清单

## 目标
把 2026 年的票据全部扫描归档，并输出一张年度收支表。

- [x] 收集纸质票据
- [ ] 扫描并命名
- [ ] 录入表格

> 关键：命名规则统一为 `YYYYMMDD-类别-金额`。

| 类别 | 预算 | 实际 |
| --- | --- | --- |
| 餐饮 | 2000 | 1860 |

```js
const total = [1, 2, 3].reduce((a, b) => a + b, 0)
```
````

页面输出（`预览`）：

- 一级 / 二级标题按层级渲染；
- **任务列表可交互显示勾选状态**（`[x]` 渲染为已勾选）；
- 引用块带左侧竖线样式；
- 表格渲染为边框表格（`remark-gfm`）；
- 代码块按语言套 `highlight.js` 语法高亮；
- 原始 HTML 经白名单清洗后渲染，脚本等危险标签会被剔除。

任务条目本身的输出（列表视图）：标题、领域、优先级、标签、`ProgressBar` 进度条 + 百分比环形图 + 状态文字；若子清单有 3 项、已完成 1 项，则进度自动显示 **33%**，勾完 3 项自动变为 **100%** 且状态更新为「已完成」并记录完成时间。

### 5.2 附件：上传不同类型 → 解析输出

| 上传文件         | 存储                       | 点预览时的输出                                                                 |
| ------------ | ------------------------ | ----------------------------------------------------------------------- |
| `notes.md`   | 二进制存 IndexedDB `files` 表 | 原样交给 Markdown 渲染器，得到富文本；点 📎 可将内容**插入任务正文**                             |
| `plan.docx`  | 同上                       | 经 mammoth 转为 HTML 后按文档样式渲染（保留标题、列表、表格）；插入正文时插入转换后的 HTML                 |
| `report.pdf` | 同上                       | 逐页抽取文本，预览顶部标注 `_PDF 共 N 页，以下为提取的文本_`，正文按 `### 第 1 页`、`### 第 2 页` … 分段输出 |
| `photo.png`  | 同上                       | 直接以图片形式在预览弹窗中显示                                                         |
| 超过 20 MB 的文件 | 不落库                      | 弹出提示「「文件名」超过 20MB，请压缩后再上传」，跳过该文件继续处理其余文件                                |

附件元信息（名称、大小、类型、上传时间、`storage_key`）记录在 `attachments` 表；删除任务 / 日志时会连同其附件一起删除。

### 5.3 打卡：周期设置输入 → 统计输出

输入（「新建打卡」）：

```text
名称：每天读书 20 页
说明：睡前读，最少 2 页也算完成
周期：每周 N 次  目标次数：3
开始日期：2026-09-01
```

输出（打卡卡片与自检断言一致）：

| 显示项 | 值                   | 说明                            |
| --- | ------------------- | ----------------------------- |
| 周期  | 本周（周一 – 周日）         | `weekly` 以自然周为周期              |
| 进度  | 完成 2/3 · 67%        | 进度条长度 = 已完成 / 目标，上限 100%      |
| 连续  | 连续 3 天              | 从今天（今天未打卡则从昨天）往回数，只统计「应打卡」的日子 |
| 里程碑 | 7 / 21 / 66 / 100 天 | 达成后自动打勾                       |
| 热力图 | 近 12 周              | 每格一天，颜色深浅对应打卡密度               |

各周期类型的判定规则（均有自检覆盖）：

| 周期类型   | 周期范围                            | 目标次数                 |
| ------ | ------------------------------- | -------------------- |
| 每天     | 当天                              | `cycle_target`（默认 1） |
| 指定星期   | 本周一 – 本周日                       | 所选星期里已过去的天数（不超过设定值）  |
| 每周 N 次 | 本周一 – 本周日                       | N                    |
| 每月 N 次 | 当月 1 日 – 月末                     | N                    |
| 每 N 天  | 自开始日期按 N 天滚动切分，如第 1–2 天为第 1 个周期 | N                    |

```json
  "reviews": [],
  "tags": [],
  "attachments": []
}
```

> 备份导出的是**结构与元数据**，附件二进制不包含在 JSON 中，需要时请单独下载附件。

## 6. 数据存储与隐私

- **当前模式：本机浏览器存储（IndexedDB）**，库名 `lifelog`，表：`users`、`tasks`、`habits`、`checkins`、`journals`、`attachments`、`tags`、`reviews`、`settings`、`files`。
- 账号密码经 PBKDF2-SHA256（10 万次迭代 + 随机盐）派生后存储，**明文密码不落盘**；会话信息存于 `localStorage`（键 `lifelog.session`，有效期 30 天）。
- 附件二进制独立存放于 `files` 表，业务表只存元数据与 `storage_key`，与云端对象存储的用法一致。
- 所有数据按 `owner_id` 隔离。
- 数据**不上传任何服务器**；清除浏览器数据会一并清除，建议每月导出一次备份。

### 在线公开版：每个人记录各自的

线上版和本地版是**同一个程序**，区别只在「怎么打开」——服务器只负责把网页发给你，不保存任何一条记录。

| | 说明 |
| --- | --- |
| 每人一份独立数据 | 任何人打开[在线链接](https://lifelog-16154.app.workbuddy.host/)都是一个**全新的空站点**，需要自己点「注册」建账号；你记的任务、打卡、日志不会出现在别人的页面上，别人的也不会出现在你这里 |
| 作者看不到任何内容 | 没有中央数据库，服务端不接触任何记录、任何密码；站点是公开的，但数据是私有的 |
| 数据跟着「浏览器 + 域名」走 | 线上版与本地版账号**不互通**；换浏览器、换设备、清缓存都会看不到原来的数据 |
| 想要跨设备 | 目前用「设置 → 导出 / 导入 JSON 备份」；换成云端数据库的改造点见 [从本机模式切换到云端](#从本机模式切换到云端) |

换句话说：它更像**一份可以分发的单机软件**，而不是一个多人协作的在线服务。这正是「不需要服务器、也不需要花钱」的代价。

## 8. 已知限制

- 数据仅存本机浏览器，**不支持跨设备同步**；换机器需手动导出 / 导入 JSON（附件不在其中）。
- 在线版是**公开可访问的空站点**：任何人打开都能自己注册，但彼此数据完全独立 —— 相当于「每人一份单机软件」，而不是多人共享系统。
- PDF 只做**文本抽取**，扫描件（图片型 PDF）没有 OCR，预览会近乎空白。
- 单个附件上限 **20 MB**。
- 无消息提醒 / 推送，无移动端原生 App（网页为响应式布局）。
- 首屏 JS 约 **785 KB**（gzip 后 247 KB），其中包含 Markdown 渲染与高亮库，尚未进一步分包。
